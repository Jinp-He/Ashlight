# Luban xlsx 数据表结构须知（实测踩过的坑）

**平时用 scripts/ 下的现成脚本就不需要读这份文件**——这些坑已在 `tablelib.py` 里固化。只有当你要**手写新的表读写代码**（或改 tablelib）时才必读，否则会读错数据还以为一切正常。

1. **数据行的 A 列是空的**。A 列只放 `##var`/`##type`/`##group`/`##` 元标记，真正的 `Id` 在 B 列。判断「是不是数据行」**绝不能用 A 列非空**——那会把每条数据行都当空行跳过。正确判据：整行非空 且 A 列不以 `##` 开头。
2. **A 列填 `##` = 该行被 Luban 注释掉、跳过导入**。表里可能有一堆「看着有数据但没进游戏」的行（实测有 25 张卡被注释）。校验/统计要把这些行视为不存在；发现某张卡「配了却不生效」，先看 A 列是不是 `##`。
3. **一个 workbook 里所有 `##var` sheet 合并成一张逻辑表**。如 `#CardInfo.xlsx` 的飞刀 token `Extra001` 单独在 Sheet2。只读第一张 sheet 会漏行，导致 `card_id`/`buff_id` 引用误报不存在。
4. **逻辑 sheet 名 ↔ 物理文件名（sheet1.xml…）不保证同序**，走 rId 关系表映射。别用 zipfile 硬读 `sheet1.xml`——会读串 sheet。**统一用 openpyxl**，按「A1 == `##var`」认数据 sheet。
5. **行号会漂移**：用户在 Excel 里增删/重排后同一张卡行号会变（实测同一张卡从 r14 挪到过 r70）。**一律按 Id 定位，写死行号迟早改错行**。
6. **Excel 独占锁**：目标 xlsx 开在 Excel 里时，openpyxl 保存和 Luban 导表都会 `PermissionError`（目录里有 `~$` 锁文件）。写前确保文件已关闭。

改 `tablelib.py` 时别把第 1、3、4 条的修复改回去。
