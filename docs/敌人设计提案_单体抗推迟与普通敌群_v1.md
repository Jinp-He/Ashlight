# 敌人设计提案：单体抗推迟与普通敌群 v1

> 状态：早期机制草案，**遭遇与 Enemy107–109 的内容已由《十组战斗场景设计 v1》取代**；本文仅保留灰甲报时者与实体音响的演变记录。尚未写入任何 DataTable。
> 审核通过后预计修改 `Enemy/#EnemyInfo.xlsx`、`Enemy/#EnemySkillInfo.xlsx`、`Enemy/#Encounter.xlsx`；单体方案还需要装置单位的抗性与绑定停机支持。

## 1. 问题判断

当前“推迟”会直接累加到目标单位唯一的 `NextRound`。多敌人战中，推迟一只只是改写威胁顺序；单敌人战中，所有控制都会命中同一条行动链，等价于持续削减敌方全部行动经济。

不建议用以下方式解决：

- 给单体敌人“免疫推迟”：会直接否定法师/战士的核心卡牌。
- 简单把 HP、伤害或 Speed 拉高：只会让没有抽到推迟的局更难，抽到推迟时仍然能锁死。
- 把普通敌人标成精英并复用“坚毅”：现有坚毅只提高打断阈值，不处理推迟；语义也不应混用。

## 2. 新思路：报时者与实体音响

核心原则：**每一个战场节拍都必须有看得见、说得通的实体来源。**

灰甲报时者不再凭空生成独立节拍，而是与一台真实存在于战场上的“共鸣音响”同时登场。报时者负责可被推迟、打断的身体攻击；音响拥有自己的血条、ATB 图标与区域伤害意图，所有节拍伤害都由音响发出。

规则：

1. 推迟身体时，身体意图完整后移，卡牌收益不缩水。
2. 音响是独立单位，有自己的意图轮换；推迟报时者不会移动音响的行动。
3. 音响拥有极高生命与“全抗性”：免疫推迟/提前、移动、晕眩、定身、打断及全部正负状态，并获得高额伤害减免。
4. 音响只做前/后排区域伤害，不做全域伤害；玩家仍能靠走位路由。
5. 音响与报时者绑定：报时者死亡时音响立即停机并清除未结算意图；音响不计入胜利条件，玩家不需要磨掉装置。
6. 音响必须有独立模型、血条、抗性图标与意图来源箭头，不能伪装成天气或无来源伤害。

这样，推迟从“让敌人什么都做不了”变成“控制报时者，同时通过站位处理音响”。它保留控制流派的爽点，也避免为了数学需要凭空造出一条不适配世界观的节拍。

## 3. 单主体普通敌人套装（报时者 + 装置）

### Enemy106 灰甲报时者（主体）

| 字段 | 候选值 |

| IsElite | false |

| IntentionSet | `A0,ES111,3;A1,ES112,3` |

定位：单主体普通遭遇的可击杀核心。身体负责可干扰的大威胁，死亡时让共鸣音响停机。

### Enemy110 共鸣音响（绑定装置）

| 字段 | 候选值 |
|---|---|
| AlternativePath | `Speaker`（需要对应资源） |
| Hp | 600 |
| Speed | 3 |
| IsElite | false |
| StartRow | Back |
| IntentionSet | `A0,ES113,2;A1,ES114,5` |
| ResistanceProfile | `All`（新增） |
| LinkedOwner | `Enemy106`（新增） |
| IsBattleObject | true（新增，不计入胜利条件） |

定位：报时者携带的高耐久战场装置。它可以被选中并显示伤害反馈，但正常策略应是击杀报时者使其停机，而不是硬拆音响。

建议的“全抗性”精确定义：

- 受到伤害降低 90%；不吃易伤。
- 免疫推迟、提前、碰撞、移动、晕眩、定身和打断。
- 免疫毒、燃烧、虚弱、脆弱及其他 Buff/Debuff。
- 不响应嘲讽，也不成为吸血、击杀奖励或“每有一个敌人”类效果的计数对象。

音响血条旁固定显示“装置 / 全抗”标签；玩家选中它时，目标预览必须提前显示 90% 减伤或“抵抗”，避免把高血量做成信息陷阱。

音响技能：

| Id | 名称 | 效果 | ExecutingCost | 目标 |
|---|---|---|---|---|
| ES113 | 重低音震荡 | 对前排所有目标造成 3 点伤害 | 2 | AllEnemy / Front |
| ES114 | 回声音浪 | 对后排所有目标造成 3 点伤害 | 5 | AllEnemy / Back |

音响按 A0 → A1 固定循环，让区域伤害明确来自场上装置。玩家可以持续推迟报时者的 10 点重击，但不能同时冻结音响；把队伍移到安全排或尽快击杀报时者都能解决音浪。

### 最小实现建议

不再新增 `AuxIntentSet`。音响直接作为第二条 `EnemyInfo` 记录进入现有 ATB 与意图系统；只补三个通用装置字段：

- `ResistanceProfile`：引用抗性方案，`All` 按上文定义处理。
- `LinkedOwner`：绑定主体的配置 Id；主体全部死亡时装置停机。
- `IsBattleObject`：装置不计入胜利条件，也不进入常规敌人数相关收益。

这比创建无实体的特殊节拍更贴合现有数据驱动方式，也允许以后复用到炮塔、图腾、祭坛等实体装置。

## 6. 首轮实测验收

1. 连续使用两次“推迟 2”后，报时者意图确实延后 4 回合，但音响意图不移动。
2. 玩家能通过换排让音浪落空；音响不能成为全域必中税。
3. 推迟、移动、控制、状态和打断作用于音响时均显示明确的“抵抗”，且不发生隐性落账。
4. 击杀灰甲报时者会让音响立即停机，清除其未结算意图，并正常结束战斗。
5. 音响不会触发击杀奖励、吸血收益或“敌人数”增益；玩家不能靠装置刷资源。
6. 不使用推迟时，E103 不能比同总 HP 的普通群怪更难；使用推迟时，也不能降成零伤害木桩。
7. E104 同屏长期维持 3~4 个活意图，且前后排至少各有一个威胁。
8. `Block=3` 与 `Stagger=18` 的两种打断提示必须在 UI 上可区分。
