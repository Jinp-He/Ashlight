## 1. 一句话概括

每个单位有**独立能量**；轮到某单位回合时，先刷新能量、抽牌，然后**只要能量够就能连续打多张牌**，回合结束清空护甲与能量。属"能量 + 卡牌"（类杀戮尖塔）模型。

## 4. "迅捷"在当前版的含义（重要：和新版不一样）

当前 `CardTypeEnum` 只有两种（`CardTypeEnum.cs`）：

- `Swift = 0` —— **迅捷行动**
- `Execution = 1` —— **执行行动**

当前版里 **"迅捷"= 时间轴上的高优先级**（`SwiftCommand` 优先级 90，仅次于防御/拦截，`SwiftCommand.cs:24`），**并不代表"免费、不限量打出"**。

> 🔁 **对照新版**：v1 设计里"迅捷"被重新定义为"不占主牌名额、可无限补充打出"。这是语义改动，实装时要注意：是复用 `Swift` 这个枚举/类型，还是新增一个"是否占用主牌名额"的标记，得在 v1 实装清单里定。

## 5. 回合结构（ATB / 离散回合）

单位靠行动条获得行动权，轮到谁就跑一遍 `TurnResolver.ExecuteTurn`（`TurnResolver.cs:38`）：

1. 回合开始 buff（燃烧/中毒/再生）
2. **刷新能量**
3. 抽牌（仅玩家）
4. **按能量连续出牌**
5. 回合结束：清护甲、衰减 buff、过载结算、能量清零
6. 行动条重启

敌人走**意图轴 / 执行轴**（`ExecutingCost` 决定轴长），不抽牌、不耗能量。

## 6. v0 → v1 的主要差异（一眼对照）

| 维度 | v0 当前（能量版） | v1 新版（已达成共识） |
|---|---|---|
| 资源 | 每单位能量（默认 3） | **取消能量** |
| 每回合出牌 | 能量够就连打多张 | **1 张主牌 + 任意迅捷副牌** |
| "迅捷"含义 | 时间轴高优先级 | **不占主牌名额、可无限补充** |
| 超额手段 | 过载（负债换能量） | 无（靠成长把主牌升级成迅捷） |
| 抽/弃 | 每角色分堆、回合末弃光重抽 5 | 沿用"弃光重抽"，张数待定 |
| 固定牌 | 无"每回合白给攻/防/移"概念 | **攻/防/移每回合保底白给** |
